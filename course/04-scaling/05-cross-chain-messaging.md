# 跨链消息、IBC 与中继

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：区分资产桥与通用消息的来源验证、顺序和超时。

## 先看一个场景

源链完成资产锁定后发送一条消息，目标链接收证明并更新应用。源链回执和消息完成各有标识。

## 核心原理

跨链消息由发送链提交、传递组件搬运并经目标验证规则认可。验证可依赖轻客户端、签名集合或其他协议机制。

## 需要区分的概念

消息编号处理顺序与去重；验证规则判断源事件可信度；中继负责送达；超时和确认决定失败如何恢复。

## 双链状态机

~~~mermaid
flowchart LR
    A[源链发出] --> B[等待源链确认]
    B --> C[中继递交证明]
    C --> D[目标验证与执行]
    D --> E[登记目标结果]
    C --> F[超时处理]
    D --> G[执行失败待处理]
~~~

| 跨链记录 | 建议字段 |
| --- | --- |
| 来源 | 源链 ID、发送合约、发送交易、消息序号 |
| 送达 | 目标链 ID、验证方式、任务状态 |
| 结果 | 目标交易、执行结果、最终确认、失败原因 |

核对超时后的退款或重试由哪一层执行，特别是资产已经锁定的场景。IBC 的具体客户端、连接和应用处理取决于接入协议，不能从中继者名推断验证规则。

## 动手练习

画出发送、证明、传递、验证、执行和确认六步。针对消息重复、源链重组、目标调用回退分别写状态。

## 自测
