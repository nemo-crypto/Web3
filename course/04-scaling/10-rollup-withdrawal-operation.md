# Rollup 提现 · 证明、等待与领取

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：追踪从 L2 退出到 L1 到账的不同状态。

## 先看一个场景

用户在 L2 发起提现并支付手续费，页面显示「已发起」。跨链服务客服看到成功回执。用户查 L1 钱包却没有余额，因为退出动作还有协议层确认和领取。

## 拆开确认链路

| 状态 | 需要的证据 | 可告诉用户 |
| --- | --- | --- |
| L2 发起 | L2 交易和退出标识 | 请求已提交 |
| 证明可用 | 可验证的状态和所需证明 | 后续可证明或提交 |
| 等待协议条件 | 挑战或证明结算状态 | 查看剩余条件 |
| 可领取或执行 | L1 条件已满足 | 用户或服务执行还需手续费 |
| 最终到账 | L1 回执及匹配资产流 | 到账并提供凭证 |

同一个产品可能还提供流动性服务，先替用户垫付目标链资产，再自行结算。两种路径要分别披露报价、费用、到账预期与失败责任方。

## 用两张账单读退出进度

小周在 L2 发起 25 单位代币的模拟提现。已有源回执和退出编号 W-17。L1 钱包现在还查不到这笔到账。这时信息表可以拆成「L2 发生了什么」「L1 发生了什么」两栏，客服至少能解释当前已知的事实。

1. 从源回执找出 W-17，核对目标网络、资产和收款人。
2. 查退出消息是否能提交证明。对需要等待协议条件的路径，保存可查看的进度。
3. 确认可领取时，再检查由用户还是服务执行，以及对应的费用与权限。
4. 查目标链回执。执行失败时保留退出标识，根据协议提供重试或人工核对。成功后校验目标资产与收款地址。

若使用流动性服务，用户可能更早收到垫付资产。用户到账和服务后续资金结算可以在两个不同时间发生，需要按实际路径解释。

## 动手练习

画出源链已扣款、L1 证明等待、领取执行失败、退款或人工处理四个页面，给每个页面写可验证的证据。不要在定时器结束时自动标记成功。

## 自测

目标链上的领取交易执行失败，源链扣款是否自动撤销？
