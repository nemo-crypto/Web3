# 钱包批量调用 · 多步授权和执行如何组合

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：按钱包能力设计组合调用、状态追踪和回退路径。

## 先看一个场景

兑换通常有「授权」和「执行」两步。团队想用批量调用减少弹窗，但一些钱包不支持。有的钱包具备组合能力，仍要确认是否支持请求需要的原子性。

## 先协商，再展示

1. 读取钱包在当前链与账户的能力，确认期望的原子要求。
2. 为用户列清每一步操作和作用，例如授权对象、额度和最终兑换数量。
3. 把调用批次 ID 与站点业务单关联，查询钱包提供的批次状态和可用回执。
4. 功能不支持时，提供逐笔流程。若逐笔授权已成功但兑换失败，展示剩余权限与撤销入口。
5. 只有匹配的回执和业务状态才能确认最终结果。

| 设计检查 | 问题 |
| --- | --- |
| 失败原子性 | 某步失败时，前面的效果是否可以保留 |
| 切换账号 | 原请求与新账户是否隔离 |
| 部分返回 | 批次状态未知时如何继续查询 |

## 用同一份购物单比较两种结果

模拟购物使用 25 个代币，动作 1 授权商户合约可使用 25，动作 2 购买。若钱包实际执行满足原子要求的两步批次，第二步回退时整次批次的状态变更应回滚。再换到只支持逐笔确认的钱包，授权回执已成功，第二笔购买回退。此时订单没支付，单独完成的授权仍可能有效。

| 页面看到的证据 | 用户需要知道 |
| --- | --- |
| 钱包返回批次标识 | 可以查找这个批次，下一步仍需查状态 |
| 批次状态未知 | 保留原请求标识继续查询，避免直接再发送 |
| 一次独立授权已成功 | 可以查看授权对象和剩余额度 |
| 购买回执及收款已核对 | 显示实际支付与业务确认情况 |

## 动手练习

准备三个钱包能力响应。A 支持原子批次，B 需要逐笔确认，C 与当前链不兼容。写出页面会展示的步骤、待确认提示和失败后的恢复动作。在 B 的流程里模拟「授权成功，兑换回退」，验收界面能说明剩余授权并连到权限检查页。
