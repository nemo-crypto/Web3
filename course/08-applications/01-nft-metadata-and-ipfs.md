# NFT、元数据与 IPFS

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：区分代币所有权、内容访问与许可权利。

## 先看一个场景

门票 NFT 的 ownerOf 显示持有者，图片从外部文件读取，能否转售与入场由其他规则决定。

## 核心原理

NFT 标准定义资产识别与转移。元数据关联图片和属性，可能来自 URL、链上数据或内容标识 CID。可持续访问还依赖内容是否有可用副本。

## 需要区分的概念

tokenId 标识合约内的资产；URI 指向描述；CID 按内容寻址；许可条款定义用户可获得的版权或其他权利。

## 用一张票认识三个链接

打开一张票的详情页，你会看到编号、图片和使用说明。查「编号 17」时，还需要知道它所在的链和发行合约。图片地址写在元数据里，可以是普通网络地址，也可以用内容标识 CID 来核对拿到的文件。门票能不能入场、是否已经用过，要分别查活动规则和核销记录。

| 当前问题 | 第一份证据 |
| --- | --- |
| 我是否持有第 17 号票？ | 正确链和合约的持有人状态 |
| 图片打不开，是票消失了吗？ | 分别核对持有人状态与内容地址可用性 |
| 可以转让或入场吗？ | 查活动规则、转让限制与实际核销记录 |

试把图片 URL 隐去，仍可以读持有人和票号。如果要查图像是否改变，再拿内容或可信来源的摘要作比较。

## 动手练习

在示例数据中记录链、合约、tokenId、URI。模拟网关离线与发行方更新 URI，分别说明如何验证内容和恢复访问。
