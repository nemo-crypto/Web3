# 托管、出入金与余额迁移

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：理解银行、交易平台、钱包之间的资金路径。

## 先看一个场景

用户使用法币入金买入代币，再提到钱包，之后转回另一平台。每一次移动都涉及不同的账户、确认要求与可能的费用。

## 核心原理

在交易平台买到代币时，平台可以先在自己的账本上把余额记给你。提到个人钱包要由平台处理一笔链上交易。提出到银行账户则走独立的法币付款流程，可能还要等银行或支付服务处理。

## 需要区分的概念

银行侧通常查付款编号，链上查交易哈希。某些平台用同一个收款地址接收多个用户的款，此时还可能要求附带 Memo 或 Tag，帮助区分实际属于哪个平台账号。

## 从银行到钱包，再从钱包回到平台

模拟用户用银行账户入金，平台确认后给他记一笔内部余额。买入代币时，平台调整现金和代币的账面记录。发起提币时才出现一笔实际的链上转移。接收方是另一个平台时，还要等对方根据入金地址和确认规则更新内部余额。

| 页面显示 | 哪份记录能证明 |
| --- | --- |
| 法币入金已受理 | 付款渠道生成的凭证或受理编号 |
| 已买入，在平台持有 | 平台成交单与账本 |
| 提币已发送 | 正确网络的交易哈希 |
| 新平台入金成功 | 回执、确认条件和新平台内部流水 |

如果入金资产需要 Memo 或 Tag，发出前就核对。已发送但接收平台仍处理中时，从链、地址、回执和 Memo 四项查起。确有错误时优先查接收方的恢复流程，避免为了验证而重复汇款。

## 动手练习

画出银行 → 平台内部余额 → 链上钱包 → 平台二次入账，标出到账证据、费用归属、异常处理责任与适当合规核查。
