## 先看一个场景

四笔账单分别遇到足额、部分、超时、重复事件。你要把模拟付款数据回放成可审计的商户流水。

## 核心原理

订单、链上事件、总账、退款都有独立主键，状态变化需有事件证据。按网络和 token 识别，金额用整数最小单位。

## 需要区分的概念

订单管理应收；事件监听识别实收；账务记录应付与收入；退款引用原交易并形成新记录。

## 固定验收数据

| 事件 | 原始金额 | 预期 |
| --- | ---: | --- |
| P1 / TX1#0 | 12,000,000 | 累计 12、仍待补款 |
| P1 / TX2#0 | 13,000,000 | 达到 25，等确认后入账 |
| P1 / TX2#0 重放 | 13,000,000 | 累计保持 25 |
| P1 / TX2#0 被重组撤销 | 13,000,000 | 冲销并回到累计 12 |
| P2 / 不受支持的资产 | 25,000,000 | 标记异常并保留人工处理记录 |

模拟代币精度为 6，P1 和 P2 的应付均为 25。交付事件处理表、订单状态图、幂等测试和对账报表。任选一笔异常画出退款审批及退款确认步骤。

## 动手练习

准备同一订单两笔付款与一条重复事件，按金额累加和确认规则记账。再加入一次重组、错误资产与退款失败的测试。

## 自测

相同交易哈希可能包含多个转账事件，应该怎样去重？
