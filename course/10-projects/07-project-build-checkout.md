# 项目六 · 搭一个可验收的链上收银台

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：结合界面、模拟回调、订单状态与故障验收，交付完整支付流程。

## 先看一个场景

课程项目要在手机和桌面完成一次模拟付款，并允许第三方按测试数据重放。服务端使用固定样本模拟链上事件和异常，页面只读取订单结果并解释下一步。

## 分成四个交付物

| 交付物 | 需要看到什么 |
| --- | --- |
| 页面 | 应付资产、网络、付款地址、订单状态与过期时间 |
| 订单接口 | 状态、历史事件、确认规则和业务操作 ID |
| 模拟监听 | 事件输入、验收结果、去重日志与手工撤回 |
| 验收脚本 | 25 USDC 正常、两笔 12.5、重放、错资产与重组样本 |

建议先通过[交互实验室](../../reference/practice-lab.md)理解对账状态，再按[收银台课程](../05-payments/12-checkout-and-fulfillment.md)设计网络接口。应用与数据使用模拟账户，提交时附上 Markdown 使用说明。

## 关键验收

1. 已支付订单再次打开会显示已确认。重复回调保持一次发货。
2. 先付 12.5 进入部分付款，第二次足额后进入确认。错资产保留异常记录。
3. 事件撤回后能冲销，保留历史原因。刷新及换页可恢复同一个订单。
4. 手机可核对网络和资产，键盘能访问所有表单。错误文案能告诉用户做什么。

## 自测

模拟服务重启，前端本地缓存还是「已支付」时，可以直接展示可发货吗？

<details>
<summary>查看参考答案</summary>

要向订单服务重新确认状态。缓存可以标为上次观察，不能替代后端已经对账的状态及履约记录。

</details>
