# 项目五 · 链上支付上线与故障演练

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：交付跨团队发布清单、对账证据和异常工单手册。

## 先看一个场景

商户版本上线后，索引延迟、节点超时和重复事件先后发生。研发、支付运营与客服要使用同一事实来源和状态语言复盘。

## 输入与验收

| 输入 | 正确业务结果 |
| --- | --- |
| P1 足额付款并确认 | 发货一次，账务新增一条实收记录 |
| P2 重复回调三次 | 同一入账状态和流水 |
| P3 源回执成功但资产不符 | 进入异常工单，保持原订单未支付 |
| P4 已入账后事件撤回 | 追加冲销记录，按规则暂停履约 |
| P5 退款提交超时 | 查原操作和回执，避免重复退款 |

## 动手练习

交付订单状态图、事件样本、核对字段、事故时间线与值班处理表。分别用普通用户、客服和开发者的视角写出状态文案。给每项恢复动作标注发起角色以及何时允许重试。

## 自测

测试全部通过，线上观察到回调成功率下降，排查时先恢复哪个条件？

<details>
<summary>查看参考答案</summary>

先对比链上证据、事件延迟与服务健康，把已确认但尚未处理的应用恢复到可重放队列。暂停无证据的重复发货或退款，等对账结果可复现后逐批恢复。

</details>
