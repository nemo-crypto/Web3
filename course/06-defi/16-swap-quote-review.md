# 聚合报价评审 · 报价方向、Gas 与落地

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：对同一报价输入比较不同路由的费用和执行约束。

## 先看一个场景

甲路由报 99 B，乙路由报 100 B。甲所需手续费折算 0.12 B，乙需要 1.25 B。按相同口径估算时，甲的净结果 98.88 B 略高于乙的 98.75 B。

## 报价评审表

| 字段 | 作用 |
| --- | --- |
| 方向与规模 | 确认输入定额或输出定额，以及相同输入金额 |
| 路由与中间币 | 查路径中每池费率和中间资产风险 |
| 报价时间 | 固定快照、时效和失效后刷新策略 |
| 预期输出和最低输出 | 将估算与合约执行约束分别展示 |
| Gas 与服务费 | 使用一致单位，避免重复扣费 |
| 执行结果 | 用回执和实际到账金额核对，支持失败重报价 |

页面提供报价来源、过期时间和实际成交记录。有特殊转账行为的资产需要单独验证支持情况。多路拆单的结果依次受各池状态影响。

## 收到的代币与钱包交的网络费分别记

两条路由都用 100 A 兑换 B。第一条预计得到 99 B，网络费约相当于 0.12 B。第二条预计得到 100 B，网络费约相当于 1.25 B。同一时点折算后，第一条净比较值为 98.88 B，第二条为 98.75 B。这个净比较值帮助挑路线，钱包实际收到的 B 要看成交，网络费则可能用另一种资产扣除。

| 操作时点 | 用户需要看见 |
| --- | --- |
| 选择报价 | 预计到账、网络费或其他手续费、更新时间 |
| 准备签名 | 最低输出、手续费资产与有效期 |
| 执行完成 | 实际收到的 B、实际网络费和回执 |
| 原报价过期 | 重新计算报价，请用户核对新条件 |

**最低输出**约束的是合约所认可的兑换结果。若业务想显示「扣掉所有费用后值多少」，应另列说明计价口径和汇率，避免把同一笔池费扣两次。

## 动手练习

为甲、乙路由加入「报价临近过期」和「执行失败」两条条件，定义重新报价时是否需要用户重新确认。明确最低输出是否包含页面标注的网络费。
