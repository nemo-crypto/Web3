# 订单簿同步 · 快照、增量与序号缺口

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：从撮合快照和连续增量重建可用市场视图。

## 先看一个场景

看盘页连续收到编号 121、122、124 的三条消息，中间少了 123。页面上的价格还能显示，但缺的那条可能刚好撤掉了一笔订单。接下来看该怎样找回可信的盘口。

## 恢复状态

| 状态 | 处理 |
| --- | --- |
| 等待快照 | 缓存有界增量和频道信息 |
| 按顺序同步 | 丢弃快照之前的更新，按接口契约应用其后连续事件 |
| 缺失或乱序 | 显示数据陈旧，按照接口规则重新取快照或补齐 |
| 重新进入实时 | 校验连接、序号和快照完整性，再恢复下游消费 |

实现时查清平台的增量语义。数量字段可能是更新后的绝对值，也可能是变化量。行情展示、模拟成交和实盘交易对陈旧数据的容忍应分别定义。

## 真的重放一份只有几行的盘口

| 序号 | 事件 | 当前观察 |
| --- | --- | --- |
| 120 | 快照显示买价 99 有 3 个单位，卖价 101 有 2 个 | 有一个可读起点 |
| 121 | 按接口规则将买价 99 更新为 1 | 买盘数量变为 1 |
| 122 | 将卖价 101 更新为 0 | 移除这一档 |
| 124 | 新增卖价 102 有 1 个 | 缺少 123，先确认连续性 |
| 124 再次收到 | 重复事件 | 按已消费序号判断是否忽略 |

**快照**表示某个时点的完整盘口。**增量**讲那之后改变的档位，字段可以是新的总数量或变化量，按平台定义读取。本题把数量视为更新后的总数量。出现缺口时即使新报价看着合理，缺的一条也可能修改了价格或库存。无法补齐就按规则重新取快照，再恢复计算。

## 动手练习

绘制一个 4 行的快照和 5 条事件，含重复序号、零数量移除与缺失序号。写出重启或断线后每一步可展示的状态。
