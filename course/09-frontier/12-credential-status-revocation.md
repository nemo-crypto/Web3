# 可验证凭证 · 签发、出示与撤销

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：区分签名有效、声明真实、持有人绑定和业务可用。

## 先看一个场景

一家合作机构带来上个月发的电子资质。你能验证它确实出自签发方，同时查到资格今天处于暂停。验签和审核资格是两步，系统要能分别给出结果。

## 四层证据

| 环节 | 核对内容 |
| --- | --- |
| 签发 | 签发者、授权范围、签名方法和生效时间 |
| 出示 | 请求方、案件、披露范围和挑战绑定 |
| 状态检查 | 业务有效期、暂停或撤销记录、更新时间 |
| 决策 | 本次的业务准入条件与可审计证据 |

把凭证当成一份可验证的声明，先查谁发出、由谁出示，再查现在能否使用。W3C 定义的状态列表是一种让验证方核对停用或撤销情况的方式。是否采用、多久能得到更新，取决于接入的签发系统。查询时也应减少对外暴露持有人的使用记录。

## 签名正确，为什么资质仍可能不生效

合作方提交了一张上月签发的核验凭证。先核对签名是否来自预期机构，随后对照本次请求、有效时间和状态。模拟机构今天把资格暂停了。这张凭证仍能证明机构上个月发过该声明，本次业务却需要按暂停规则处理。

| 读取情况 | 业务处理 |
| --- | --- |
| 签名不匹配 | 标记证据未通过来源校验 |
| 签名有效且状态正常 | 再核对持有人、时间、用途与准入要求 |
| 签名有效但已暂停 | 按规则暂停本次准入并提供说明 |
| 状态服务超时 | 标记「待核验」，按失败策略重试或人工处理 |

这里四条记录要留作彼此独立的证据：谁签发、谁在出示、能否查询当前状态、本次审核为什么通过或失败。设计查询时也要考虑是否会暴露持有人的每次使用行为。

## 动手练习

模拟凭证签名正确、凭证已暂停、验证服务无法连接三个状态。为每个状态写下可告知用户的结果和可重试入口，避免把网络失败直接等同于撤销。
