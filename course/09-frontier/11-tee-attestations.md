# 可信执行环境与远程证明

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：看懂证据、验证者和业务策略，解释硬件证明的边界。

## 先看一个场景

一个结算服务声称在受保护环境运行计算。集成团队希望验证执行环境和程序版本，并防止拿以前生成的证据来应付新请求。

## 远程证明的分工

| 组件 | 处理内容 |
| --- | --- |
| 被证明方 | 生成与环境、程序测量和请求上下文相关的证据 |
| 验证方 | 按参考值和证明策略核对证据 |
| 依赖方 | 结合验证结果、业务授权和时效决定是否接受 |
| 供应者 | 提供有关设备、证书或平台实现的材料 |

远程证明可以说明在某一组假设下运行环境符合条件。验证者仍需管理平台依赖、引用程序版本、证据新鲜度、撤销和潜在漏洞。证明结果也要绑定业务输出和输入承诺。

## 动手练习

设计只接受经过批准的程序版本且挑战 ID 一次有效的结算服务。写出证明有效、程序版本不合格、挑战不是本次、证书过期四种情况。

## 自测

证明来源可信，是否就能证明模型答案或者外部输入一定正确？

<details>
<summary>查看参考答案</summary>

环境证明、执行规则、输入数据真实性与业务结果分别需要证据。只有把输出、输入和程序绑定到验证请求，才能说明这次结果满足已定义的部分条件。

</details>
