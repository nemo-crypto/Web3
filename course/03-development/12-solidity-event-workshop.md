# Solidity 事件实训 · 业务状态与索引字段

[课程首页](../../README.md) · [本阶段](README.md)

> **学完能做到**：将本地的订单核销状态、日志与读取结果对应起来。

## 先看一个场景

前端显示活动票已核销，但索引器没有收录那条事件。开发者需要确认合约状态、交易回执和索引延迟，不能仅据界面判断是否成功。

## 从结构设计开始

| 项目 | 示例 |
| --- | --- |
| 当前状态 | redeemed[ticketId] 查询票券是否已用 |
| 事件标识 | Redeemed(ticketId, holder, gateId) |
| 可检索字段 | 经常筛选的票 ID、持有人、约定的索引字段 |
| 来源证据 | 链 ID、合约地址、交易哈希、日志索引、区块哈希 |
| 状态更新约束 | 核销失败时保留原状态，回执中不得出现已完成事件 |

## 本地练习

1. 在本地开发链创建两个模拟地址和一个虚拟票券。
2. 对同一票券完成一次合法核销，再尝试一次重复核销。
3. 对每笔操作记录回执、事件和读取结果。给索引任务加入一次暂时失联，再从上次确认区块回扫。
4. 使用一次合法转让或后续操作证明「谁核销了」与「当前状态」可以有不同查看入口。

## 自测

事件被索引成功，为什么仍要按业务需要读取合约当前状态？

<details>
<summary>查看参考答案</summary>

日志是历史执行证据。之后的状态变更、索引滞后或重组都可能影响当前判断。历史展示与实时权限检查应按各自的输入查询。

</details>
